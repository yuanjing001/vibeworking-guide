# 上下文管理(Context)

> Context 不是某个工具的"功能",是模型的"记忆"。**用得差,模型就降智。**

::: tip 本页原则对所有场景通用
例子以开发场景(Claude Code)为准,因为它把上下文状态量化得最清楚 —— `/context` 能直接看到占用比例。
**但「一次别塞太多」这条原则,和你在 WorkBuddy 里整理几十页文档、让 AI 读一整个季度数据,是同一件事。** 桌面工作台没有 `/context` 命令,但「聊到后面开始忘事、答非所问」的症状完全一样,对策也一样:分段、分批、别一次给全部。
:::

## 一句话本质

AI 模型一次能看见的 token 上限 = **它的全部工作记忆**。对话越长,这个记忆越满。装到 60% 后,你会肉眼看到模型开始忘事、答非所问、自我矛盾。

## Context 的 6 阶段生命周期

```mermaid
加载(CLAUDE.md + 项目文件)
  ↓
任务(你的 prompt)
  ↓
思考(中间步骤、读取的文件)
  ↓
输出(diff / 解释)
  ↓
总结(滚动摘要,后台)
  ↓
压缩(到上限后强制)
```

Claude Code 默认走前 5 步,**不到 60% 不要手动 `/compact`**(详见下文)。

## 5 条硬指标

| 指标 | 阈值 | 含义 |
|------|------|------|
| Context 占用 | 60% | 模型能力下降分水岭 |
| 对话轮次 | 3 轮 | 没完成就该拆了 |
| 单条 prompt | ≤ 1 屏 | 太长说明你没想清楚 |
| `@codebase` / `@folder` | 单次 ≤ 1 | 多了 context 立刻撑爆 |
| 项目文件 import | ≤ 2 层 | 跨多文件 AI 容易丢上下文 |

## 8 个管理技巧

### 1. 写好 CLAUDE.md(让关键信息每次都重新加载)

详见 [Prompt 写法](/workflow/prompt#让好-prompt-可复用)。

### 2. 显式 `@` 引用

不要让 AI 自己"找文件"——显式告诉它:

```
请只参考 @src/services/order.ts 和 @src/models/order.ts 这两个文件
```

### 3. 拆任务(最有效的工作流)

**别让 AI 一次做完所有事**。拆成 3-5 步,每步独立验证:

```
步骤 1:加接口骨架 + 类型
步骤 2:实现核心逻辑(单元测试)
步骤 3:加错误处理 + 日志
步骤 4:集成测试 + 文档
```

每步之间 `/clear`。

### 4. 不用 `/compact`,用 `/clear`

社区共识:**`/compact` 会丢信息**。直接 `/clear` + 把关键约束再粘一次更稳。

### 5. 错误回复不纠正,clear + 重写

详见 [迭代与调试](/workflow/iteration#错了不纠正-重来一次)。

### 6. 工具输出"瘦身"

如果某个工具返回了一大段 JSON / 日志,问 AI:

```
请只保留 [关键字段],丢掉其余噪音
```

让 AI 自己裁剪。

### 7. 长任务开"分会场"

大重构 / 长调试:

```bash
# 用 git worktree 开一个独立分支
git worktree add ../myproj-fix-bug -b fix/bug-123
cd ../myproj-fix-bug
claude
```

每个 worktree 独立 context,互不干扰。

### 8. 监控 context 用量

| 工具 | 怎么看 |
|------|--------|
| Claude Code | `/context` 命令,显示当前占用比例 |
| Trae IDE | 顶部右侧 token 数字 |

**剩 40% 就准备拆**,别等满了才动。

### 桌面工作台怎么判断「装满了」

WorkBuddy 这类桌面应用没有 `/context`。判断依据是**症状**,不是数字:

| 你观察到 | 实际发生了什么 | 怎么办 |
|---------|--------------|-------|
| 越聊越短,刚开始要求详细现在只给几行 | 模型在省 token | 停下,分段重发 |
| 反复提你早先说过的事 | 早期信息被截断 | 停下,重新交代背景 |
| 突然开始动没提过的文件 | 它在乱找 | 显式告诉它看哪几个 |
| 同一问题前后答案不一样 | 前后信息冲突 | 停下,用新会话重来 |

**出现任何一条,立刻开新会话,不要试图在原会话里纠正。** 理由和开发场景完全一样:上下文已被污染,纠正只会让它更乱。

### 桌面场景的分段原则

| 做法 | 为什么 |
|------|-------|
| 一份材料一个任务,别攒着一起问 | 每个任务上下文独立,不会互相污染 |
| 长文档分批喂,喂完先让它总结 | 总结就是压缩,给下一批腾空间 |
| 明确说「只看这几个文件/这几页」 | 减少无关内容占用 |
| 换任务就换会话 | 最重要的一条 |

## Context 撑爆的 5 个症状

| 症状 | 原因 |
|------|------|
| AI 答非所问 | 已经忘了一开始的 prompt |
| 输出越来越短 | 在"省 token" |
| 反复重复之前说过的话 | 早期信息被截断 |
| 引入无关文件 / 代码 | 在乱搜 |
| 自相矛盾 | 同一问题前后两个答案不一样 |

**任何症状出现 = 立刻 `/clear` + 重发 prompt**。
