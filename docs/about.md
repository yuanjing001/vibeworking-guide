# 体系说明

> 首页回答「我从哪开始、能做出什么」;这一页回答「本站怎么组织内容、现在做到哪」。

## 一句话定位

**Vibe Working(人机协同工作范式)= 人主导方向与判断 + AI 承担执行与探索 + 多轮持续迭代共创。**

本站是一个**泛职场**人机协同指南,面向所有想用 AI 把工作做得更好的人,**不按职业分轨**。编程只是工作场景之一 —— 运营、财务、工程师面对的是同一套方法:定义问题、人机分工、验收结果。

本站不是工具说明书,也不按厂商组织内容。工具是载体,方法才是长期资产 —— 详见[基础认知 · 方法优先,工具为载体](/concepts#方法优先-工具为载体)。

## 适合谁

| 谁 | 典型工作 | 能拿走什么 |
|----|---------|-----------|
| **泛职场人** | 运营、产品、市场、行政、财务、人力、工程师、学生、自由职业者 | 用 AI 把文档、数据、调研、方案、代码做得更快更好;先学判断与验收,再按任务选工具 |

不需要写代码也能学;工程师也不需要另开一条线 —— 你只是选了不同的任务场景。

## 学习路径

学习分三段:**基础认知 → 工具主线 → 补充与实战**。三段的学习顺序、产出与验收标准见[学习路径](/learning-map)。

内容按 5 层架构组织。

## 5 层架构

```
第 5 层  底层基建     Agent Runtime 底座、基准评测、私有部署、团队级落地
   ▲                 面向高阶用户,深度定制
   │
第 4 层  进阶方法论   任务拆解、多 Agent 协同、提示词工程、MCP 生态
   ▲                 所有场景在此汇合
   │
第 3 层  场景实践     写作 / 文档 / 数据 / 工程 / 自动化   ← 核心内容区
   ▲                 按工作场景组织,不分职业轨
   │
第 2 层  工具范式     5 大类工具图谱(CLI / IDE / 办公 / 聚合 / Runtime)
   ▲                 工具库索引,持续新增
   │
第 1 层  基础认知     Vibe Working 定义、人机分工、通用底层能力   ← 全员必修

   ══════════════════════════════════════════════════════
   横向原则   安全与验证 · 结果校验   ← 贯穿以上所有层次
   ══════════════════════════════════════════════════════
```

**五层是内容的组织层次,不是学习顺序。** 学习只需要看三段([学习路径](/learning-map))。

### 五层不是五级台阶

一个擅长任务拆解的运营可能第一次接触 Agent;一个熟悉 Git 的工程师可能完全不懂模型上下文与工具权限。**不必从第一层一路读到第五层。**

## 第一期计划

| 优先级 | 缺什么 | 为什么重要 |
|-------|-------|-----------|
| **P0** | **办公类场景剧本(已上线 1 篇,还差 3 篇)** | 最大的断点。读者现在学得到方法,但还缺「跟我这份 Excel 一样的完整剧本」 |
| **P1** | 交互式选型器 | 现在只有静态对照表,读者得自己判断 |
| **P2** | 2.4 类工具词条 | Cherry Studio 等,目前只有分类没有词条 |

办公类场景的推进计划:

1. 多文档信息提取与汇总(最通用)
2. Excel 数据清洗与结果校验(最高频)
3. 周报 / 汇报 PPT 生成(交付物明确)—— [周报剧本已上线](/playbook/weekly-report)
4. 竞品调研(最能体现「验证」的价值)

这 4 个场景各自能检验一件事:工具分类能不能支持真实选择?方法论能不能用上?推荐工具之后有没有可执行路径?工作流有没有明确验收标准?

## 内容承诺

- **方法先行**:先讲怎么把事做对,再讲用哪个工具、点哪里;场景内容统一分「方法篇 + 工具篇」
- **任务制**:每个任务有产出物与验收标准,不按工具菜单组织内容
- **不按职业分轨**:写作、数据、工程是工作场景的差别,不是人的差别;编程只是其中一种形式
- **三类实体不互相复制**:工具资料 / 场景工作流 / 方法论资产,通过链接连接,工具更新只改一处
- **安全横向贯穿**:不是某一章,而是所有实战的必读项
- **诚实标注**:未上线的部分明确写「筹备中」,待验证的假设明确标注
- **定期复核**:工具词条标注核验日期,过期会提醒

## 如何贡献

每篇内容带结构化元数据(`type` / `audience` / `level` / `status` / `prerequisites` / `verified_at`),由脚本在构建时校验词表。新增内容需满足三要素:

1. 属于 Vibe Working 范畴(人机协同、多轮迭代、人主导)
2. 能归入现有 5 层架构中的某一层
3. 有明确的适用场景,最好带一个真实任务

贡献方式见 [GitHub 仓库](https://github.com/yuanjing001/vibeworking-guide)。内容以 CC BY-NC-SA 4.0 开源,站点代码以 MIT 发布,欢迎 PR。
