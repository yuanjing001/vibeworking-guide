# WorkBuddy 实战配方:10 个真实工作流

> 工具词条解决「它是什么」;这一页解决「拿它干什么、怎么干、怎么验收」。
>
> 配方对应[工具主线](/tool-mastery)里 WorkBuddy 的 10 项用透清单。**一次只做一个,每个都留一个真实产出。**

## 怎么用这一页

- **一次只做一个配方**。一天做完 10 个,不如一周吃透 1 个。
- **每个配方都走完整链路**:准备 → 操作 → 指令 → 产出 → 验收 → 坑。
- **界面以官方版本为准**。这里按「能力」组织步骤,不绑定具体按钮位置。
- **配方 1-3 是日常**,4-6 是提效,7-10 是自动化与沉淀。按顺序打怪升级。

## Recipe 01 · 用 Plan 模式做一份活动方案

**场景**:下周要做 Q4 预热活动,你只有一个目标和预算,方案还没影。

**用到的能力**:三种模式里的 Plan(先方案、后执行)。

**准备**:

- 目标:拉新 / 促活 / 转化,分别要什么数
- 约束:预算、时间、可用的渠道
- 历史参考:上一次同规模活动的数据

**步骤**:

1. 切到 **Plan 模式**(只出方案,不动文件)
2. 把目标、约束、历史数据一起给它
3. 要求它输出:策略、渠道、预算分配、排期、风险
4. 你改一版,再切 **Craft** 执行物料清单

**指令**:

```
目标:Q4 预热活动,拉新 5000,预算 5 万,周期 3 周。
渠道:公众号、社媒、站内。
历史:上次同预算活动拉新 3200,成本 15 元/人。

请先用 Plan 模式输出:
1. 3 个策略方向,每个说明预期拉新和成本
2. 推荐哪个,为什么
3. 渠道预算分配(加总=5 万)
4. 3 周排期
5. 主要风险与应对

先不要写文案,等我确认方案。
```

**产出**:一份可评审的活动方案(背景 / 目标 / 策略 / 渠道 / 预算 / 排期 / 风险)。

**验收**:

- [ ] 三个策略都有数字依据,不是形容词
- [ ] 预算加总等于 5 万
- [ ] 每个风险都有应对
- [ ] 方案里写清了「假设」,比如转化率按多少估

**坑**:Plan 默认给的是「正确但泛」的方案。**逼它写假设和验证方式**,否则你拿到的是 PPT 话术。

## Recipe 02 · 多 Agent 并行做竞品调研

**场景**:一周内要对比 3 个竞品,手动查资料至少两天。

**用到的能力**:多 Agent 并行(一个需求拆成多个子任务)。

**准备**:

- 竞品名单(3 个)
- 统一对比维度:定价、核心功能、目标用户、渠道、近 3 个月动作
- 信息来源要求:官网 / 公开报道,禁止编造

**步骤**:

1. 建一个总任务,拆成 3 个子任务(每个竞品一个)
2. 给所有子任务同一份「对比模板」
3. 并行执行,先收结果不评价
4. 你合并、去重、补来源,再让 AI 写结论

**指令**:

```
并行调研 3 个竞品:A、B、C。
每个竞品按同一模板输出:
- 定价(套餐 + 价格 + 是否有免费版)
- 核心功能(最多 5 条)
- 目标用户
- 主要渠道
- 近 3 个月公开动作(带日期和来源链接)

要求:
- 每条信息必须有来源链接
- 找不到就写「未找到」,禁止推测
- 最后输出一张横向对比表
```

**产出**:一张对比表 + 3 条结论(谁在抢谁的用户、本团队差异点、建议动作)。

**验收**:

- [ ] 每个关键信息能点回来源
- [ ] 没有「据说」「可能」这类词
- [ ] 结论能对应到具体数据,不是感觉

**坑**:并行任务最容易「格式各不相同」。**先定死模板,再并行**;否则合并比调研还累。

## Recipe 03 · 定时任务自动出周报初稿

**场景**:每周五写周报,素材散在文档、待办、聊天记录里。

**用到的能力**:定时任务(cron 风格)。

**准备**:

- 一个固定的「本周素材」文件夹或文档
- 周报模板(成果 / 进展 / 问题与方案 / 下周计划)
- 一个明确的产出位置

**步骤**:

1. 新建定时任务,频率设为每周五 15:00
2. 任务内容:读取素材 → 按模板生成初稿 → 标注「待确认」
3. 生成后通知你,不要自动发送
4. 你花 15 分钟校准,再发

**指令**:

```
每周五读取「本周素材」文件夹,按以下结构生成周报初稿:
1. 本周核心成果(≤3 条,结果 + 数据 + 价值)
2. 关键进展
3. 问题与方案
4. 下周计划

要求:
- 只用素材里出现的事实和数字
- 缺失的标「待确认」,禁止编造
- 把初稿写到「周报草稿」文档,不要发送给任何人
```

**产出**:每周五下午的一份初稿。

**验收**:

- [ ] 初稿是「半成品」,不是自动发出去的终稿
- [ ] 每条成果都能在素材里找到依据
- [ ] 你能在 15 分钟内改完

**坑**:定时任务自动化的是**执行**,不是**判断**。自动发送 = 事故;永远留人工确认。

## Recipe 04 · 把周报流程做成 Skill

**场景**:团队 5 个人写周报,格式、重点、质量参差不齐。

**用到的能力**:Skills(把固定流程打包成可复用技能)。

**准备**:

- 一份团队公认的「最佳周报」样例
- 结构、字数、验收规则
- 3 份不同岗位的输入素材

**步骤**:

1. 新建 Skill:名称、触发方式、输入要求、步骤、输出模板
2. 把「验收清单」写进 Skill,而不是只写生成步骤
3. 用 3 份素材测试,记录失败案例
4. 修到新人也能产出合格初稿,再分享给团队

**Skill 结构(可直接抄)**:

```
名称:团队周报助手
触发:用户提供本周素材 + 岗位
输入:3 个成果、关键数字、卡点、下周计划
步骤:
1. 按「成果 / 进展 / 问题与方案 / 下周」生成初稿
2. 逐条检查是否有数据支撑
3. 输出「待确认清单」
输出:800 字以内周报 + 待确认项
验收:每条成果有数字;每个问题有方案;无编造
```

**产出**:一个团队可用的周报 Skill。

**验收**:

- [ ] 新人第一次用就能产出 70 分初稿
- [ ] Skill 里包含验收规则,不是只有 prompt
- [ ] 不同岗位的素材都能跑

**坑**:Skill 写得太泛(「帮我写周报」)等于没写。**输入格式和验收标准必须固定。**

## Recipe 05 · MCP 接内部系统查数据

**场景**:每次汇报都要登录后台复制订单数据,再粘到表里。

**用到的能力**:MCP(把内部系统 / 数据库接成 AI 可调用的工具)。

**准备**:

- 一个**只读**账号或 API
- 明确字段口径:订单数、GMV、退款率怎么算
- 先确认公司数据政策允许

**步骤**:

1. 在工作台设置里添加 MCP 服务(从只读开始)
2. 权限最小化:只给需要的库 / 表
3. 先用一个已知答案的问题测试,比如「查上周订单数」
4. 确认口径一致后,再让它在任务里取数

**指令**:

```
查上周(周一到周日)的订单数据:
- 订单数
- GMV
- 退款率

按区域拆,输出表格;最后用 3 句话总结环比变化。
只读查询,不要写任何数据。
```

**产出**:一条「取数 → 分析 → 写结论」的工作流。

**验收**:

- [ ] 查询结果和后台手工核对一致
- [ ] 只有读权限,没有写 / 删权限
- [ ] 查询口径写进了提示词或文档

**坑**:一上来就给写权限、把密钥写进 prompt、用生产库做实验 —— 这三件事任意一件都可能出事。

## Recipe 06 · 批量处理 80 份 PDF 合同

**场景**:80 份合同 PDF,要提取甲乙方、金额、签署日期、到期日,做一份台账。

**用到的能力**:批量文件处理。

**准备**:

- 字段清单(必须提取哪几列)
- 3 份代表性样本(清晰扫描件 + 模糊扫描件 + 特殊格式)
- 文件命名规则

**步骤**:

1. 先只跑 3 份样本,确认字段能提取
2. 你人工核对这 3 份,修正字段定义
3. 全量跑,输出 Excel
4. 抽查 10%,关键字段(金额、日期)100% 人工复核

**指令**:

```
读取这个文件夹里的合同 PDF,逐份提取:
合同名称、甲方、乙方、合同金额、签署日期、到期日、付款方式。

输出一张 Excel 表,每行一份合同,最后加一列「文件名」。
提取不到的字段写「未识别」,不要猜。
金额只保留数字和币种。
```

**产出**:一份合同台账 Excel。

**验收**:

- [ ] 抽查 10% 与原件一致
- [ ] 金额、日期全量人工复核
- [ ] 原始 PDF 有备份,没有被覆盖
- [ ] 含敏感信息的文件按公司规定处理

**坑**:扫描件 OCR 质量、合同模板不统一、隐私外泄。**先样本、再全量**是铁律。

## Recipe 07 · 本地模式处理敏感数据

**场景**:薪酬 / 绩效 / 客户名单,不能上传云端。

**用到的能力**:本地模式(数据不离开终端)。

**准备**:

- 确认工作台已切到本地模式
- 做一份脱敏样例
- 明确输出里不能出现哪些字段

**步骤**:

1. 切本地模式,必要时断网
2. 先跑脱敏样例,确认输出格式
3. 再处理真实数据
4. 导出结果后,清理会话与临时文件

**指令**:

```
基于本地文件汇总各部门薪酬中位数和分位数。
输出只保留部门、人数、中位数、P25、P75,不要输出任何姓名和工号。
如果做不到脱敏,停止并告诉我。
```

**产出**:一份脱敏汇总表。

**验收**:

- [ ] 数据全程没有离开终端
- [ ] 输出里没有姓名、工号、身份证等字段
- [ ] 会话和临时文件已清理,没有分享链接

**坑**:任务切了云端、MCP 把数据发出去、顺手截图发群 —— **本地模式不是保险箱,流程才是。**

## Recipe 08 · 企微 / 腾讯文档联动

**场景**:会议纪要在企微、方案在腾讯文档、待办在聊天记录,散得到处都是。

**用到的能力**:腾讯生态集成。

**准备**:

- 绑定企业微信 / 腾讯文档账号
- 指定会议录音或文档链接
- 纪要模板:结论 / 待办 / 负责人 / 截止时间

**步骤**:

1. 绑定账号,确认权限范围
2. 指定一次会议或一份文档
3. 生成纪要,提取待办
4. 你核对人名和截止时间,再同步回文档 / 群

**指令**:

```
读取这次会议的录音/转写,输出:
1. 3 条关键结论
2. 待办清单:事项、负责人、截止时间
3. 未决问题

只根据录音内容整理,不要补充没说过的话。
人名和日期不确定的标「待确认」。
```

**产出**:一份会议纪要 + 待办清单。

**验收**:

- [ ] 每条待办有负责人和截止时间
- [ ] 人名、日期与录音一致
- [ ] 敏感会议先确认了权限,没有自动外发

**坑**:自动同步到群、录音权限过大、把「讨论」写成「决议」。**发出前必须人工确认。**

## Recipe 09 · 控制积分与任务粒度

**场景**:这个月积分用得快,但产出没变多。

**用到的能力**:成本意识(不是功能,是用法)。

**准备**:

- 最近 2 周的任务清单
- 每个任务的产出与消耗记录(估个大概)
- 哪些任务返工最多

**步骤**:

1. 把大任务拆小:一次只做一件事
2. 素材先筛选:别把 50 页 PDF 全喂进去
3. 复杂任务先 Plan,减少返工
4. 批量任务合并,减少重复上下文
5. 一周后对比:产出 / 消耗

**指令**:

```
不要一次处理全部素材。先读目录和前 2 页,
列出你需要的文件和字段,等我确认后再逐份处理。
每次只输出当前这一份的结果。
```

**产出**:一张「任务 → 产出 → 消耗」对照表。

**验收**:

- [ ] 单任务平均消耗下降
- [ ] 产出质量没有下降
- [ ] 知道了哪类任务最烧积分

**坑**:为了省而省,把任务拆得无法完成;重复生成同一份内容才是最贵的。

## Recipe 10 · 沉淀 3 个自己的模板

**场景**:每次写周报、方案、汇报,都从零开始想 prompt。

**用到的能力**:模板化。

**准备**:

- 挑 3 类你每月至少做 1 次的任务(周报 / 方案 / 汇报)
- 每类留一份「最好的一次」产出
- 一份验收清单

**步骤**:

1. 每类写一个骨架:角色 / 任务 / 约束 / 输出格式
2. 把「验收清单」附在模板后面
3. 存到 WorkBuddy 的 Skill 或团队文档
4. 每月复盘一次:哪条约束没用、哪条总在救火

**模板骨架**:

```
角色:你是我的[周报/方案/汇报]助手。
任务:基于[输入],产出[输出]。
约束:
- 只用我给的事实和数字,缺失标「待确认」
- 不写过程,只写结果和判断
- 遇到冲突信息,先问我
输出:结构 + 字数 + 格式
验收:每条结论有依据;每个问题有方案
```

**产出**:3 个可复用模板。

**验收**:

- [ ] 新人能直接拿去用
- [ ] 模板里有验收,不只有生成
- [ ] 每季度更新一次

**坑**:模板写完就放那、不写验收、不随工具版本更新。

## 最后:配方不是终点

10 个配方跑完,你手里的不是 10 条技巧,而是:

- 一套**取数 / 处理 / 交付**的流程
- 一份属于自己的**模板库**
- 一张知道**哪里会出错**的避坑清单

下一步:把这些配方里最常用的 1-2 个,变成你的 Skill 或定时任务。**工具用透的标志,是重复的事不再从零开始。**
