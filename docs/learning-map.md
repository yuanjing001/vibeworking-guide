# 学习路径

> **先建认知,再把工具用透,最后补安全与验收。** 顺序比目录重要 —— 不用从头读到尾,但别跳过第 1 段直接上工具。

<LearningMap />

**路线看全貌,下面看每一段学什么、按什么顺序、什么算学完。**

## 怎么用这条路径

1. **按段走**:第 1 段(基础认知)→ 第 2 段(工具主线)→ 第 3 段(补充与实战)。
2. **每段有产出**:不是「读完」,是「做出一个东西」。每段末尾有验收标准。
3. **可以局部加速**:已经懂概念的,可以直接进第 2 段;但**别跳过验收标准**。

::: tip 不想按顺序?
如果你手上已经有明确的活要交,可以直接去[实战剧本](/playbook/weekly-report)做完再回来补认知 —— 但回来补一次,你会知道刚才哪里没做对。
:::

<a id="part-1"></a>

## 第 1 部分:基础认知(1-2 小时)

> 「先搞清楚:哪些事归你,哪些事归 AI。」

**为什么先学**:工具会用错,通常不是操作问题,是分工没想清楚。先知道 AI 会编、会自信地错、没有你的目标感,后面用工具才不会被带偏。

### 按这个顺序学

| 顺序 | 内容 | 产出 |
|------|------|------|
| 1 | [基础认知](/concepts):人机分工、幻觉、提示词四要素 | 能说出「哪些判断必须自己做」 |
| 2 | [快速开始](/getting-started):选一个真实任务,装好工具 | 跑通第一个任务 |
| 3 | (可选)[从这开始](/start):20 分钟做完第一份周报 | 一份能交差的产出 |

### 学完的标准

- [ ] 你能说出:这个任务里,AI 负责哪部分、你负责哪部分
- [ ] 你知道 AI 会在哪些地方编(数字、引用、文件路径)
- [ ] 你有一个真实的、能交付的产出

<a id="part-2"></a>

## 第 2 部分:工具主线(1-2 周)

> 「把 1-2 个主流工具用到位,而不是每个都摸一下。」

**为什么这是主线**:基础认知决定方向,工具决定你能不能真的把活干完。这一段的目标不是「知道有哪些工具」,而是**至少把一个工具从 L1 练到 L3/L4**(定义见[工具主线](/tool-mastery))。

### 按这个顺序学

| 顺序 | 内容 | 产出 |
|------|------|------|
| 1 | [工具主线](/tool-mastery):4 级进阶模型 + 每工具练习清单 | 选定你的主工具 |
| 2 | 选一个主工具:[WorkBuddy](/workbuddy) / [Trae IDE](/trae-ide) / [Claude Code](/claude-code) | 跑通它的 3 个常用工作流 |
| 3 | 按「7 天进阶计划」练:真实任务 → 模板化 → 进阶功能 → 边界 | 一份模板 + 一份避坑清单 |
| 4 | 需要定制时再进 [DeepSeek Harness](/deepseek-harness) | 一个能跑的自定义 Agent |

> 选了 WorkBuddy?可以直接跟[10 个真实工作流](/workbuddy-recipes)练;选了 Trae?先看[实战案例精选](/trae-cases)。
>
> **模型怎么选**是跨工具的能力:换工具不换判断顺序,见[模型怎么选](/model-selection)。

### 学完的标准

- [ ] 同一个任务做第二次,比第一次快一半
- [ ] 你能说出这个工具**不擅长**什么,以及什么时候该换工具
- [ ] 你至少有 1 个可复用的模板 / Skill / 提示词

<a id="part-3"></a>

## 第 3 部分:补充与实战(持续)

> 「安全、方法、真实任务 —— 把工具能力变成交付能力。」

**为什么放在后面**:没上手工具之前,安全与验收只是抽象条款;用过之后再看,每一条都对应你踩过的坑。

### 按这个顺序学

| 顺序 | 内容 | 产出 |
|------|------|------|
| 1 | [安全与验证](/safety):权限、数据、不可逆操作 | 一份自己的安全检查清单 |
| 2 | [进阶方法论](/workflow/prompt):Prompt / Context / 迭代 / Review | 一套稳定的工作方法 |
| 3 | [实战剧本](/playbook/weekly-report):周报 / 加功能 / 修 Bug / 重构 | 完整走完至少一个任务 |
| 4 | 自动化与团队:[定时任务](/workbuddy) / [多 Agent](/deepseek-harness) / SOP | 一条可复用的流程 |

### 学完的标准

- [ ] 你的每个交付都有明确的验收动作,不是「看起来不错」
- [ ] 你知道哪些数据不能进 AI、哪些操作必须人工确认
- [ ] 你能把流程交给别人复用,不依赖你在旁边讲

## 能力刻度(参考)

> 「入门 / 熟练 / 进阶 / 专家」这套刻度不用背,按上面三段走就行。

| 能力刻度 | 对应阶段 | 典型表现 |
|---------|---------|---------|
| **入门** | 第 1 部分 | 能分辨 AI 给的和自己判断的 |
| **熟练** | 第 2 部分 | 一个工具用到 L3,能稳定交付 |
| **进阶** | 第 3 部分 | 完整工作流 + 验收 + 自动化 |
| **专家** | 第 3 部分之后 | 团队 SOP、权限规范、Agent 系统 |

## 常见问题

### 能不能先学工具,再补基础认知?

可以,但建议至少先读[基础认知](/concepts)里「人机分工」和「幻觉」两节 —— 否则你会在错误的方向上把工具用得很熟练。

### 工具主线要学几个工具?

**1-2 个就够。** 先精通一个,再扩展第二个。多工具同时学,通常每个都停在 L2。

### 安全与验证为什么放最后?

作为**课程顺序**它在后面;作为**动作**它必须每次动手前发生。第 3 部分是把零散的安全意识变成你自己的检查清单。

### 一共要学多久?

第 1 部分 1-2 小时;第 2 部分 1-2 周(每天 30-60 分钟);第 3 部分是长期能力,边做边沉淀。**按「能独立交付什么」衡量,不按读完多少篇。**
