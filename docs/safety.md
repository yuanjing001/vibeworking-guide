# 安全与验证

> **横向原则 · 不属于任何单一层次。** 这一页同时约束第 1 到第 5 层 —— 无论你用哪个工具、哪个层次的工作流,执行前后都要走这里的检查。

## 先看一个真实的翻车现场

一位职场用户让 AI 整理桌面上的季度资料。任务本身没问题 —— AI 也把汇总做出来了。

问题出在同目录下还有一份**客户名单**。用户没提这个文件,AI 也没问,直接把整个目录读进去做了汇总。三周后,这份含客户信息的汇总被发到了外部。

**没有人恶意,也没有人失职。** 只是没有人告诉 AI「不要碰什么」。

这个场景和「让 Agent 跑生产部署」的风险类型**完全一样**:范围没划清,就把判断权交出去了。

::: danger 风险不看你处在第几层
新手第一次让 AI 批量处理文件,和专家第一次让 Agent 跑生产部署,面对的是同一类问题:**AI 默认什么都能碰,除非你说清楚不能碰什么。**
:::

安全不做成横向页,就会只在某一章里出现 —— 而读者读到那一章时,通常已经准备执行了。

## 60 秒判断:这四个问题

时间紧?执行前只回答这四个问题,能避开绝大多数风险:

| # | 问题 | 不答的后果 |
|---|------|-----------|
| 1 | 交付物是什么?什么算做对了? | 做完才发现要的不是这个 |
| 2 | **哪些绝对不能碰?** | AI 动了不该动的 |
| 3 | 数据里有敏感信息吗? | 泄露 |
| 4 | 出问题怎么回滚? | 无法挽回 |

第 2 和第 4 是大多数人跳过的两个 —— 也是出事最多的两个。

## 执行前 · 三件事必须先说清

在按下执行之前,这三件事要**写出来**,不是心里想。

### 1. 目标与范围

| 问自己 | 例 |
|--------|-----|
| 交付物是什么? | 一份 6 页的竞品分析 PPT |
| 哪些文件/数据是范围内的? | `~/Documents/Q3销售明细.xlsx` |
| **哪些绝对不碰?** | 其他所有文件 |

**「不碰什么」比「做什么」更重要。** 把边界写进 prompt,而不是指望 AI 自己判断。

### 2. 数据权限

| 数据类型 | 能不能发给外部模型 |
|---------|-------------------|
| 公开信息 | 可以 |
| 内部未公开数据 | 先确认工具的数据政策 |
| 客户个人信息 / 身份证 / 金融账户 | **不发给外部模型** |
| 商业机密 / 未公开财报 | **不发给外部模型** |
| 密钥、令牌、密码 | **永远不** |

**本地模式 ≠ 自动安全**,它只是数据不经过第三方服务器。模型本身仍然在生成内容。

### 3. 不可执行的操作

明确写出**禁止 AI 执行**的动作:

```
禁止:
- 删除或覆盖任何文件
- 执行 git push / 任何远程写操作
- 执行系统级命令(装包、改权限)
- 发送到外部网络
```

## 执行中 · 检查点与人工确认

不是所有步骤都能自动跑。**这些节点必须停下来,由人确认**:

| 节点 | 为什么要停 |
|------|-----------|
| AI 说「我将修改以下文件」 | 确认范围没超出预期 |
| 批量操作超过 N 个文件/行 | 范围失控的信号 |
| 任何删除、覆盖、发送动作 | 不可逆 |
| AI 要执行 shell 命令 | 可能是破坏性的 |
| 数据要离开本地 | 权限边界 |

**小步执行**是最有效的安全手段:每步可回滚,出错了损失可控。

## 执行后 · 验收与回滚

### 验收标准要在执行前就定好

不是「看起来不错」,而是可执行的检查:

| 类型 | 验收方式 |
|------|---------|
| 数据处理 | 抽查 N 条,核对数字;行数对得上 |
| 文档产出 | 对照原始需求逐条核对 |
| 代码改动 | 看 diff + 跑测试 |
| 调研结论 | 要求给出处,自己核实 |

### AI 会自信地编造

| 幻觉类型 | 表现 | 防御 |
|---------|------|------|
| 编造数据 | 给出「据统计」的数字 | 数据必须来自你给的输入 |
| 编造来源 | 引用不存在的链接/文档 | 让它给出来源,自己核实 |
| 编造结论 | 基于不存在的数据推论 | 检查推理依据是否真实存在 |
| 过度自信 | 「这是最优方案」 | 要求给 trade-off |

**通用判据:凡是具体的、可验证的事实,一律自己确认一遍。**

### 回滚方案

执行前就确认:**出问题怎么退回去?**

| 场景 | 回滚方式 |
|------|---------|
| 代码改动 | `git diff` + `git checkout .` |
| 文件处理 | 备份原文件,或用 git 追踪 |
| 数据处理 | 保留原始数据副本,不在原文件上直接改 |
| 对外发送 | 发出前确认,不撤回 |

**不可逆的操作(删除、付款、发外部),要么别让 AI 做,要么人工确认。**

## 高危操作清单

看到这些,停下来:

| 高危信号 | 为什么 |
|---------|--------|
| `rm -rf`、`del /s`、强制推送 | 不可逆删除 |
| 执行来源不明的脚本 | 供应链风险 |
| 把 `.env`、密钥内容发给模型 | 凭据泄露 |
| 在生产环境直接执行 AI 的命令 | 影响真实用户 |
| AI 说「顺便也改了 X」 | 范围失控 |

## 每个工具的权限模型

| 工具 | 默认权限 | 新人怎么设 |
|------|---------|-----------|
| [Claude Code](/claude-code) | 危险操作询问 | 保持询问,跑顺了再放宽 |
| [Trae IDE](/trae-ide) | sandbox 内文件读写 | 网络/系统命令手动授权 |
| [WorkBuddy](/workbuddy) | 本地/云端双模式 | 敏感数据走本地模式 |
| [DeepSeek Harness](/deepseek-harness) | 可执行代码和命令 | 保持授权确认,别全放开 |

## 写给团队

个人风险可控,团队风险需要制度:

- 明确哪些数据不能发给外部模型
- 明确哪些操作必须人工审批
- 高危操作留审计记录
- 把踩过的坑写进项目规则文件

## 自检清单

每次让 AI 动手前:

- [ ] 目标交付物说清楚了吗?
- [ ] 「不碰什么」说清楚了吗?
- [ ] 数据分级检查过了吗?
- [ ] 禁止操作列出来了吗?
- [ ] 不可逆操作有人工确认点吗?
- [ ] 出问题怎么回滚,想过吗?

**执行后:**

- [ ] 抽查过结果,不是只看它说成功?
- [ ] 数字和来源核实过吗?
- [ ] 改动范围在预期内吗?
