## 核心定位

DeepSeek AI 开发的**开源 Agent Harness 框架**(命令 `dsh`),基于 Cordis 的「一切皆插件」架构,MIT 协议。

**一句话:前四类工具是「用 AI 干活」,这一类是「造一个干活的 AI」。**

| 维度 | 说明 |
|------|------|
| 归属 | DeepSeek AI(非字节) |
| 形态 | 本地运行,Web UI 或桌面客户端 |
| 许可 | MIT,可自由使用 / 修改 / 商用 |
| 当前状态 | 开发者预览版 v0.1,**会有破坏性变更** |
| 强项 | 模型、工具、沙箱、UI 全部可替换 |
| 门槛 | 需要会用命令行、能读英文文档 |

::: warning v0.1 是预览版
核心插件与基础接口仍在快速迭代,**未来会出现破坏兼容性的变更**。生产环境使用请自行评估。
:::

## 它和前四类的根本区别

前面四类工具,你用的是**别人配好的 Agent**;这一类,你配的是**Agent 本身**。

| 类 | 你在做什么 |
|----|-----------|
| 2.1 ~ 2.4 | 用别人的 Agent 完成你的任务 |
| **2.5** | **定义 Agent 该用什么模型、什么工具、什么循环** |

判断你**是否真的需要这一层**:

- 只是想用 AI 提高效率 → 停在 2.3 / 2.4 就够了
- 成品工具满足不了你的特定需求 → 上 2.5

**不要为了「先进」而上这一层。** 大多数人用不到。

## 核心概念:一切皆插件

模型、工具、技能、会话、沙箱、存储、循环、调度、UI —— **所有 Agent 能力都是插件,可以自由替换、重组。**

这带来三个直接结果:

| 特性 | 含义 |
|------|------|
| **无特权内核** | 不存在「需要打补丁的内核」,扩展方式是挂插件 |
| **可替换** | 模型适配器、工具注册表、Agent 循环本身都能换 |
| **卸载即撤销** | 各项注册都是副作用,插件卸载时自动撤销 |

**对使用者的意义**:你可以把 2.4 类工具做不到的事情做出来 —— 比如强制某个 Agent 只能用特定模型、只能在隔离沙箱里跑。

## 四种运行模式

| 模式 | 默认加载 | 适合 |
|------|---------|------|
| **标准模式** | 完整工具组合 | 绝大多数日常任务,开箱即用 |
| **PTC 模式** | 程序化工具调用 | 模型生成一段代码组合多轮调用,编排成一次流程 |
| **极简模式** | 仅 shell + 文件编辑 | 最小环境下的模型基准测试 |
| **创造模式** | — | 检查运行时、在内存中试验插件、创作新模式 |

**建议路径**:先用标准模式跑通 → 需要复杂编排时试 PTC → 做基准测试用极简 → 造新能力用创造。

## 10 分钟上手 Demo

### 1. 启动 Web UI

需要已安装 Node.js:

```bash
npx @deepseek-ai/dsh web
```

然后浏览器打开 `http://127.0.0.1:3080`。

**Web UI 在你本机启动,不走第三方服务器** —— 项目文件、API Key、会话数据都留在本机。

### 2. 或者装桌面客户端

不想用命令行:直接下载 Windows / macOS 客户端,安装即用。

### 3. 跑一个真实任务,先确认它能用

```
读一下当前目录的项目结构,告诉我入口在哪
```

**在装插件之前,先确认基础能力正常。** 基线不稳时排查问题会很痛苦。

### 4. 从源码装(要做定制时)

```bash
git clone https://github.com/deepseek-ai/deepseek-harness
```

## 可观测性:每一次运行都有迹可循

这是这一层工具最被低估的价值 —— **它把「AI 为什么这么做」变成了可回放的数据**。

| 特性 | 说明 |
|------|------|
| **仅追加日志** | 系统提示词、思维链、工具调用与结果、子 Agent 调度、每次上下文注入,全部写入 |
| **按来源查看** | Trajectory 视图可按来源查看,还原运行轨迹 |
| **同一份事件流** | 恢复、分叉、检索、回放共享同一事件流 |
| **可重建** | 抵达模型请求的一切都能从日志重建,并由运行时断言校验 |

**模型可见即已记录。** 当 Agent 行为不符合预期时,你可以直接回放看它当时看到了什么 —— 这在成品工具里做不到。

## 避坑指南

| 坑 | 表现 | 解法 |
|----|------|------|
| **不该上却硬上** | 花大量时间配插件,不如直接用成品工具 | 先确认成品真的满足不了需求 |
| **v0.1 当稳定版用** | 升级后插件全废 | 生产环境锁定版本 |
| **还没跑通就装插件** | 出问题不知是基础不稳还是插件问题 | 先用标准模式确认基线 |
| **命令记不住** | 反复查文档 | 收藏:标准 / PTC / 极简 / 创造 四模式 |
| **以为它是 DeepSeek 专用** | 以为绑定了 DeepSeek 模型 | 模型适配器本身就是插件,可换 |

### 安全提醒

它能在你的电脑上执行代码和操作,**权限要自己把关**:

- 文件操作保持授权确认,别全放开
- 敏感数据用本地模式处理
- 接入 MCP 插件时,按 [基础认知 · MCP 接入顺序](/concepts#技术概念速查)逐步验证

## 同类工具对比

同类:**2.5 Agent Runtime 底座**。与相邻类分工:

| 需求 | 选谁 |
|------|------|
| 自定义 Agent 编排、换模型 / 沙箱 / 工具 | **DeepSeek Harness** |
| 直接用现成 Agent 干活(办公) | [WorkBuddy](/workbuddy)(2.3) |
| 多模型切换开箱即用 | 2.4 类工具(筹备中) |
| 长周期代码重构 | [Claude Code](/claude-code)(2.1) |
| 编辑器内跨文件改 | [Trae IDE](/trae-ide)(2.2) |

**与 Claude Code / Codex 的区别**:dsh 是**开源 MIT 的框架**,可自由替换模型、工具、沙箱;Claude Code、Codex 是闭源的成品编码智能体。

**与 DeepSeek Chat 的区别**:DeepSeek Chat 是开箱即用的对话产品;dsh 是拿来**搭**智能体的开源框架。
