# 模型怎么选:7 个场景 + 5 个判断问题

> **不问「哪个模型最强」,问「这一步该派谁上」。**
>
> 本文方法来自 [TRAE 官方公众号 · 模型怎么选](https://mp.weixin.qq.com/s/e_EJbRbLqykZfffBEwJhGQ) 的社群经验整理,并补上「换工具后怎么用」的对照。模型名称、价格、倍率都会随平台变化,文中提及仅作**判断示例**,不是官方评测或推荐。

## 先记判断顺序,再记模型名

模型列表会一直变,判断顺序不会。遇到任何任务,按这五问走:

### 1. 这个任务的返工成本高不高?

- **低**:改 bug、写小功能、跑初稿、做格式转换 → 先用便宜 / 快的模型,允许多试几轮
- **高**:项目从 0 到 1、架构设计、大需求拆解 → 在关键节点用一次强模型,买的是「不用推倒重来」

> 日常小任务的真实成本 = 调用次数 × 单价。一个要来回三五轮的任务,单价就是决定性变量。

### 2. 需不需要看图?

要贴报错截图、还原设计稿、走查 UI → **先把不支持多模态的选项筛掉**。

一个小技巧:先让模型「完整提取图片原文,不要总结」,确认它没读错,再让它分析。识图失误会让后面所有推理都建立在错误信息上。

### 3. 改的是新代码还是老代码?

- **老项目**:优先选「克制、不乱重构」的模型;先建立全局认知、输出影响面清单、确认边界,再动手
- **大范围跨文件改动**:优先选大上下文模型,保证改动连贯

### 4. 产物给谁看?

- 页面 / H5 / 小程序 → 把「审美」当硬指标,代码能跑不等于页面能看
- 纯后端逻辑 / 脚本 → 不用为审美付费

### 5. 你愿意花多少力气写提示词?

习惯大白话口述、不想先写规整 spec → 把「中文理解」权重调高;反之可以选更「吃指令」的模型。

## 7 个场景对号入座

> 下表来自社群用户的主观推荐,不是能力排名。模型名会变,看「选择逻辑」即可。

| 场景 | 用户高频选择(示例) | 为什么这么选 | 什么时候升级 / 降级 |
|------|------------------|-------------|-------------------|
| 日常改 bug、写小功能 | GLM-5.3-Flash、DeepSeek-V4-Flash | 试错成本低,能多跑几轮 | 卡住两三轮后升 Pro;问题已被趟过雷,Pro 更容易一次中 |
| 报错截图、UI 走查、设计稿还原 | GLM-5.3-Flash、Kimi-K2.7-Code | 原生多模态,省掉人肉转译 | 先提取图片原文,再分析;读错就换模型 |
| 项目从 0 到 1、架构设计 | Kimi-K3、GLM-5.3 | 一次规划到位,避免全盘返工 | 只在起步 / 关键节点用,后面交给便宜模型 |
| 老项目维护、遗留改造 | DeepSeek-V4-Pro、GLM-5.3 | 改动克制 + 大上下文连贯性 | 先要影响面清单,再动手 |
| 前端页面、样式、H5 | Qwen3.8-Flash、Kimi 系列、Seed-2.1-Pro | 代码审美,减少手工调样式 | 先看 1-2 个页面效果,再决定是否全量 |
| 大白话口述需求 | Seed-Code、GLM-5.3、DeepSeek-V3 | 中文理解稳,不用反复雕琢提示词 | 需求越模糊,这项权重越高 |
| 写文档、review、项目梳理 | GLM-5.3-Flash、Qwen3.8-Flash | 长上下文 + 低消耗 | 先让它出结构,再补细节 |

## 四套组合拳(按预算)

| 打法 | 组合 | 适合 |
|------|------|------|
| **打窝式编码** | 先用便宜 Flash 跑初稿 / 搭架子 / 跑测试,卡住再升 Pro | 日常高频、返工成本低 |
| **预算充足** | 强模型一路走到底 | 关键项目、时间比钱贵 |
| **性价比** | 强模型做架构与评审 + 中档模型做后端 + 便宜模型做前端 | 大多数个人开发者 |
| **极致性价比** | 中档做架构 + 便宜做前端/后端 + 强模型只做终审 | 预算敏感、愿意多轮验收 |

**起步建议**:把一个便宜的 Flash 设成默认,遇到搞不定的再往上升级。这是社群里最多人在用的方式。

## 换工具后怎么用:相似工具合并说明

**判断顺序与工具无关。** 换工具只换执行端,下面按「工具类别」合并说明,不用在每个工具页重复一遍:

| 工具类别 | 同类工具(合并说明) | 模型选择怎么落地 |
|---------|-------------------|----------------|
| **2.3 办公 Agent 工作台** | WorkBuddy、TraeWork、千问办公 | 办公任务默认低倍率;长文档 / 汇报选长上下文;截图、设计稿选多模态;敏感数据走本地模式 |
| **2.2 AI 原生 IDE** | Trae IDE、Cursor | 小改动用便宜模型;项目起步 / 架构用强模型;前端看审美;老项目选「克制」的模型 |
| **2.4 多模型聚合客户端** | Cherry Studio、LobeChat、Open WebUI | 最需要自己配:把「默认便宜 + 关键升级」写成两套配置 |
| **2.1 CLI 编码 Agent** | Claude Code、Gemini CLI、Codex CLI | 模型多与工具绑定;重点放在 Plan 模式、上下文控制与权限,而不是频繁换模型 |
| **2.5 Agent Runtime** | DeepSeek Harness | 把判断固化成路由:默认模型 / 升级模型 / 多 Agent 角色分配 |

### 四个主流工具的具体用法

- **WorkBuddy**:内置多模型切换。批量整理、定时任务用低倍率;长文档汇总、汇报用长上下文;截图和设计稿用多模态;敏感数据切本地模式。
- **Trae IDE**:模型列表里按场景选。小改动 Flash;项目起步强模型;前端 Qwen / Kimi;老项目 DeepSeek-Pro;配合 Rules 把偏好固定下来。
- **Claude Code**:模型选择相对固定,重点是用 Plan Mode 先规划、控制上下文、小步提交;复杂任务用强模型,批量脚本不要硬上最贵的。
- **DeepSeek Harness**:可自定义模型路由。把「默认便宜 + 关键节点升级」写成配置,多 Agent 按角色分配模型。

> 具体模型名、倍率、可用性以你打开工具时为准。**不要背模型名,背判断顺序。**

## 什么时候不该换模型

- 连续失败 2-3 轮,先怀疑**提示词 / 上下文 / 任务拆解**,而不是继续换模型
- 同一个任务换了三个模型都做不好,大概率是任务定义有问题
- 为了省积分把任务拆到无法完成,反而更贵

## 一张卡片带走

```
1. 返工成本高吗?    低 → 便宜模型多试;高 → 关键节点上强模型
2. 要读图吗?        要 → 只选多模态
3. 新代码还是老代码? 老 → 选克制;跨文件 → 选大上下文
4. 产物给谁看?      给用户看 → 审美是硬指标
5. 提示词成本?      爱口述 → 中文理解优先
```
