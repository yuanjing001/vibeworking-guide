# 工具主线:把主流工具用透

> 基础认知之后,主线不是「多试几个工具」,而是**把 1-2 个主流工具用到位**:主功能 → 组合工作流 → 自动化 / 定制。

## 什么算「用透」

工具用浅了,你只是在「让它回答」;用透了,它才真的替你干活。四个层级:

| 层级 | 你会做到 | 证据 |
|------|---------|------|
| **L1 会打开** | 装好、登录、跑通第一个任务 | 有一个真实产出,不是 demo |
| **L2 会用主功能** | 模式选择、文件读写、上下文引用、结果校验 | 能独立完成常见任务 |
| **L3 会组合工作流** | 多文件、多步骤、模板、Skill、跨工具串联 | 有一份自己的提示词 / 模板库 |
| **L4 会定制与自动化** | 定时任务、MCP、多 Agent、脚本 / Runtime | 重复任务能自动跑,别人也能复用 |

> **判断标准**:同一个任务做第二次,你能不能比第一次快一半?不能,说明还在 L2。

**先选一条主线**:办公类任务从 WorkBuddy 开始;需要动代码从 Trae IDE 或 Claude Code 开始;要定制 Agent 再进 Harness。**不要四个一起学。**

**模型选择是跨工具的能力**:同一套判断顺序,换工具不用重学 —— 见[模型怎么选:7 个场景 + 5 个判断问题](/model-selection)。

## 每个工具的用透清单

> 下面的清单可以直接当练习计划。每一项都要有一个「真实产出」,不要只点一遍菜单。

### WorkBuddy(办公主线)

- [ ] 三种模式的选择:Craft / Plan / Ask,知道什么任务用哪个
- [ ] 多 Agent 并行:把一个大任务拆成几个子任务同时跑
- [ ] 定时任务:每周自动生成周报初稿 / 竞品信息
- [ ] Skills:安装一个现成 Skill,再把自己的固定流程写成 Skill
- [ ] MCP:接入一个内部系统或数据源(从只读权限开始)
- [ ] 批量文件处理:重命名、归档、格式转换
- [ ] 本地模式处理敏感数据,知道什么不能进云端
- [ ] 腾讯生态:企微 / 腾讯文档 / 会议纪要的联动
- [ ] 成本控制:积分消耗与任务粒度的关系
- [ ] 沉淀 3 个自己的模板(周报 / 方案 / 汇报)

→ 进阶内容:[WorkBuddy 10 个真实工作流](/workbuddy-recipes)

### Trae IDE(编辑器主线)

- [ ] 三种交互:Chat / 选区精修 / Composer 跨文件
- [ ] 项目规则文件:`.rules` 或 `AGENTS.md` 写清技术栈与约束
- [ ] 上下文引用:精确引用文件 / 目录,而不是让 AI 自己找
- [ ] 跨文件改动:一次改 3 个以上文件,并看懂完整 diff
- [ ] 预览与回滚:改完先看效果,再决定是否保留
- [ ] MCP 接入:数据库 / 文档 / 浏览器
- [ ] 不适用场景:CI、部署、长任务,知道什么时候换 CLI

→ 进阶内容:[TRAE 实战案例精选(8 个案例)](/trae-cases)

### Claude Code(终端主线)

- [ ] 安装与登录,跑通第一个真实改动
- [ ] `CLAUDE.md`:项目规则、启动 / 测试命令、禁止项
- [ ] Plan Mode:复杂任务先出计划再执行
- [ ] 权限白名单:哪些命令允许、哪些必须询问
- [ ] 小步提交:一步一验证,出问题能精准回滚
- [ ] 长任务:拆解、恢复、上下文管理
- [ ] 脚本化:`claude -p` 接进自动化流程
- [ ] 多 Agent / 子任务:什么时候值得拆

### DeepSeek Harness(定制主线)

- [ ] 安装与配置,跑通一个最小 Agent
- [ ] 插件机制:理解「一切皆插件」的边界
- [ ] 给 Agent 接工具(文件 / 命令 / 网络)
- [ ] 编排多个 Agent 完成一条工作流
- [ ] 评测:怎么判断改完的 Agent 更好
- [ ] 私有部署与权限边界
- [ ] 与成品工具的分工:什么该自己搭,什么不该

## 三个组合配方

| 配方 | 流程 | 适合 |
|------|------|------|
| **办公 → 工程** | WorkBuddy 写方案 → Claude Code 落地成脚本 / 页面 | 运营、产品做自动化 |
| **工程 → 办公** | Claude Code 处理数据 → WorkBuddy 做汇报 / PPT | 工程师输出业务结果 |
| **个人 → 团队** | 自己的模板 / Skill → 定时任务 → 团队 SOP | 想沉淀团队资产 |

**工具组合的价值不在「多」,在「衔接」**:上一个工具的输出,正好是下一个工具的输入。

## 7 天进阶计划(选一个工具)

| 天 | 做什么 | 产出 |
|----|--------|------|
| Day 1 | 用它完成一个你本来就要做的真实任务 | 一份可交付成果 |
| Day 2 | 同一个任务再做一次,记录哪些步骤可以模板化 | 一份模板草稿 |
| Day 3 | 学它的一个进阶功能(多 Agent / Plan / 规则文件) | 一次进阶用法记录 |
| Day 4 | 把它接进一个多步骤流程 | 一条完整工作流 |
| Day 5 | 试它的一个边界(不擅长什么、什么会出错) | 一份避坑清单 |
| Day 6 | 把流程自动化或沉淀成 Skill | 一个可复用资产 |
| Day 7 | 教别人用一遍,收集卡点 | 一份使用说明 |
