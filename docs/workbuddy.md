## 核心定位

腾讯云 CodeBuddy 团队推出的 **AI Agent 桌面智能体工作台**(俗称「小龙虾」),2026 年 3 月公测。

**它和普通 AI 对话工具的分水岭:它能执行,不只能给思路。**

传统 AI 帮你「提供思路」,你还要自己动手做;WorkBuddy 直接把自然语言需求交付成**可验收的成品** —— PPT、Excel、报表、文案、网页、代码。

| 维度 | 说明 |
|------|------|
| 归属 | 腾讯云 CodeBuddy 团队 |
| 形态 | 桌面客户端(Windows / macOS)+ 云端沙箱双模式 |
| 强项 | 办公场景全覆盖、多 Agent 并行、腾讯生态集成 |
| 技术门槛 | 低 —— 不写代码,装完即用 |
| 数据安全 | 本地模式数据不离开终端 |

## 适用场景

| 适合 | 不适合 |
|------|--------|
| 写周报 / 月报 / 汇报 PPT | 需要深度定制内核 |
| Excel 批量清洗、统计分析、可视化 | 纯工程化的 CI / 部署脚本 |
| 长文档润色、翻译、多文档汇总 | 长时间运行的终端自动化任务 |
| 竞品调研、行业分析、会议纪要 | — |
| 定时任务(每天抓竞品 / 每周生成周报) | — |
| 企业内部:合同审阅辅助、跨系统联动 | — |

## 三大工作模式

**这是 WorkBuddy 最该先记住的部分** —— 选对模式能省掉大量返工。

| 模式 | 行为 | 什么时候用 |
|------|------|-----------|
| **Craft** | 你说,它做,立即交付 | 需求定义清楚的具体任务 |
| **Plan** | 先出步骤化方案,你确认后执行 | 多步骤复杂任务 |
| **Ask** | 只问答分析,**不动文件** | 方案讨论、技术咨询 |

**默认从 Craft 开始;任务超过三步就切 Plan;只是想问就用 Ask。**

## 10 分钟上手 Demo

### 1. 装上

- 官网:https://www.workbuddy.cn/ (中文俗称「小龙虾」)

| 系统 | 安装方式 |
|------|---------|
| macOS | 下载 `.dmg` 拖入 Applications |
| Windows | 下载 `.exe` 安装 |

### 2. 登录

用腾讯云账号登录。**新用户有免费积分**,签到和社区发文都能攒,足够跑完整个第一期。

### 3. 第一个任务:选一个你真的要交差的东西

别拿「试试玩」的任务上手 —— 用真实任务才能感受到它省了多少时间。

```
把这份销售明细表按区域汇总,算出各区域环比,
做成一张带折线图的 Excel,再写 3 句结论。
```

**注意任务描述里包含了**:做什么(汇总 + 环比)、要什么形式(Excel + 图表)、产出什么(3 句结论)。这三项就是 [4 要素 prompt](/workflow/prompt)里的「任务」和「输出格式」。

### 4. 换一个模式再试一次

同样的数据,切到 **Plan 模式**,让它先给步骤:

```
先告诉我你会怎么处理,列步骤,等我确认再执行
```

你会更清楚它在做什么,也更容易在中途叫停。

## 典型工作流

```
1. 装上并登录,用真实任务上手
2. 选模式:Craft(简单)/ Plan(复杂)/ Ask(只问)
3. 描述任务时带上:做什么 + 要什么形式 + 什么标准
4. 复杂任务先在 Plan 模式对齐方案
5. 拿到产物 → 人工验收(数据准确性、结论是否成立)
6. 满意 → 沉淀成 Skill,或设定时任务让它定期跑
```

### 值得优先尝试的能力

| 能力 | 说明 |
|------|------|
| **多 Agent 并行** | 一个需求拆成多个子任务并发执行 |
| **定时任务** | cron 风格:每天自动抓竞品、每周自动生成周报 |
| **Skills 生态** | 兼容 OpenClaw Skills 协议,可安装扩展 |
| **MCP 支持** | 挂载内部系统 / 数据库 / SaaS 作为工具入口 |
| **腾讯生态集成** | 原生对接企业微信、腾讯文档、腾讯会议 |
| **多模型切换** | 内置 Kimi、MiniMax、GLM、DeepSeek、Hunyuan 等 |

**定时任务是这一类工具的杀手级功能** —— 把「每周五写周报」变成自动化,才是从「AI 帮我写」升级到「AI 帮我跑完整工作流」。

::: tip 写得快 ≠ 写得好
WorkBuddy 能把你从「整理素材 + 排版」里解放出来,但哪些算成果、价值怎么定性、风险怎么报,仍然是你的判断。完整方法见 [实战剧本 · 写好一份周报](/playbook/weekly-report)(方法篇 + 工具篇)。
:::

## 避坑指南

| 坑 | 表现 | 解法 |
|----|------|------|
| **用 Ask 模式让它改文件** | 说了半天它不动 | Ask 只问答,改文件要切 Craft / Plan |
| **任务描述只说做什么,不说要什么** | 给了一堆文字,不是你要的 PPT | 一定要说清产出形式 |
| **不核对数据就交差** | 数字错了直接发出去 | **数字必须自己核对** —— AI 会编 |
| **小任务也开 Plan 模式** | 流程变啰嗦 | 三步以内的直接 Craft |
| **企业数据随手丢进去** | 合规风险 | 本地模式处理敏感数据,见下 |

### 数据安全

- **本地模式**:数据不离开你的终端 —— 处理敏感文件时优先用
- **云端模式**:由腾讯云合规机房承载
- 文件操作需要用户授权,**别图省事关掉所有提示**
- 企业场景支持私有化部署、SSO、数据审计

## 同类工具对比

同类:**2.3 成品办公 Agent 工作台**。

| 工具 | 一句话 | 侧重 |
|------|-------|------|
| **WorkBuddy** | 腾讯云出品,桌面 Agent 工作台 | 办公全场景 + 腾讯生态 + 定时任务 |
| TraeWork | 本体系词条筹备中 | — |
| 千问办公 | 本体系词条筹备中 | — |
| [Claude Code](/claude-code)(2.1) | 终端 CLI | 代码 / 脚本 / 自动化 |
| [DeepSeek Harness](/deepseek-harness)(2.5) | Runtime 底座 | 自定义拼装 Agent |

**与 CodeBuddy 的关系**:两者同源共底座,分别面向「办公」与「开发」两条产品线。CodeBuddy 走 IDE / 插件 / CLI 三形态,偏开发。

**怎么和本体系其他工具配合**:

```
WorkBuddy(办公产物:报告、PPT、Excel)
    ↓ 需要落地成代码时
Claude Code / Trae IDE(开发)
    ↓ 需要定制专属 Agent 时
DeepSeek Harness(Runtime 底座)
```
