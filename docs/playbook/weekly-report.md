# 实战剧本 · 写好一份周报

> 任务 · 写作与汇报。交付物:一份发给直属上级的周报。
>
> **先做,再看方法。** 顶部是「你会做出什么」和「10 分钟快速版」;想做得更稳,再往下读方法篇与工具篇。

| 项目 | 内容 |

| **产出物** | 一份能直接发给上级的周报 |

## 你会做出什么(示例)

下面是同一个人的同一周,两种写法的差别。

### 原始素材(节选)

```
- 周一活动启动会,方案改到第三版
- 周三转化率掉了:2.0% → 1.2%,让研发查,是落地页 JS 报错,当天修了
- 调研做了 12 份:用户说登录麻烦、导出格式少、手机加载慢
- 和设计对物料,还差一版
- 下周活动要上线,调研结论要给产品
```

### 直接让 AI 代写(流水账)

> 本周完成了活动方案的修改与讨论,并对转化率数据进行了分析,定位并修复了相关问题。用户调研已完成 12 份,收集了用户反馈。设计物料正在推进中。下周将继续推进活动上线和调研结论同步。

结构完整、语句通顺,但**没有重点、没有数据、没有判断**。领导看完还得追问一遍。

### 按方法改写后

> **本周核心成果**
> 1. Q4 活动方案定稿:覆盖 3 个渠道,预计触达 5 万用户;物料完成 60%,下周二齐套。
> 2. 用户调研 12 份:提炼 3 个高频痛点,已进入需求池,产品认领 1 个。
> 3. 转化率异常:周三从 2.0% 掉到 1.2%,当天定位为落地页 JS 报错,修复后周五回升至 2.0%,影响控制在 48 小时内。
>
> **问题与方案**
> 1. 物料依赖设计排期,有 2 天风险。方案:已确认优先级;若周三前不能齐套,启用备选物料,活动按期上线。
> 2. 登录链路痛点需要研发排期。方案:已提需求,建议下个迭代排入;本周先上线引导文案缓解。
>
> **下周计划**
> 1. 物料齐套并完成上线验收(周四)。
> 2. 输出调研结论一页纸,同步给产品和老板(周三)。
> 3. 跟进登录链路需求排期(周五)。

### 这份周报做对了什么

| 改动 | 对应方法 |
|------|---------|
| 三条成果都带数字和结果 | 结果优先、量化优先 |
| 问题都带了方案 | 让领导做选择题,不是问答题 |
| 下周计划有日期和验收 | 计划可对齐 |
| 删掉了「推进」「继续」之类过程词 | 只写结果和价值 |

### 领导可能追问什么(提前补上)

| 可能追问 | 提前补什么 |
|---------|-----------|
| 「5 万用户怎么算的?」 | 写清口径:渠道粉丝数 × 触达率,或标注「预估」 |
| 「预算低 12%,效果会不会打折?」 | 补一句依据:上次同规模活动的实际数据 |
| 「登录链路的需求为什么现在才提?」 | 说明调研时间和需求提交时间,避免看起来像拖延 |

**写周报时提前回答这三个问题,比发出去再解释省力得多。**

## 10 分钟快速版

第一次用,先走这个版本;熟练后再看下面的方法篇与工具篇。

### Step 1:抓三行素材(2 分钟)

- 本周做过的 3 件事
- 能支撑它们的数字或结果
- 一个卡点 + 你倾向的解法

### Step 2:让 AI 出初稿(3 分钟)

```
你是我的周报助理。基于以下信息,按「本周成果 / 关键进展 / 问题与方案 / 下周计划」写周报初稿。

本周 3 个成果:
[三行]

关键数字:
[数据;没有就写"暂无"]

卡点:
[卡点 + 倾向的解法]

下周 3 件事:
[三件]

要求:
1. 每条成果 = 结果 + 数据 + 价值,不写过程
2. 问题必须带 1-2 个方案
3. 只用我给出的数字;缺的标「待确认」,禁止编造
4. 全文不超过 800 字
```

### Step 3:校准四问,改到能发(4 分钟)

1. 每个数字都能回源吗?
2. 成果有没有被说小或说大?
3. 每个问题都带方案了吗?
4. 有没有 AI 编的数字、人名、日期?

### Step 4:发送前自检(1 分钟)

- [ ] 领导能在 1 分钟内看懂本周结果
- [ ] 没有不该公开的信息
- [ ] 通读一遍:像不像你本人写的
- [ ] 把提示词存下来,下次复用

> 想先跟一遍完整流程,可以看[从这开始](/start)的 20 分钟版本。

## 方法篇:什么才算一份好周报

> 示例为什么能写成那样?下面是可复用的判断标准。**方法不依赖工具** —— 换任何工具,这一篇都不用重写。

### 周报在解决什么问题

周报是**向上管理的沟通工具**,不是工作日志。三个目的,缺一不可:

| 目的 | 让领导得到什么 | 常见错误 |
|------|--------------|---------|
| 展示成果 | 你本周创造了什么价值 | 只列动作(「推进了 XX」) |
| 同步风险 | 哪里卡住了、需要什么支持 | 只报问题,不带方案 |
| 对齐预期 | 下周重点是否一致 | 计划含糊、优先级不明 |

**判据**:领导看完这封周报,能不能在 1 分钟内回答三个问题 —— 这周做成了什么?有什么需要我协调?下周重点对不对?

### 好周报的四条标准

1. **结果优先,动作垫后** —— 先写「完成了什么、带来什么变化」,再写「做了哪些事」
2. **量化优先,形容词垫后** —— 「覆盖 3 个渠道,触达 5 万用户」优于「效果不错」
3. **风险带方案** —— 每个卡点至少给 1 个你倾向的解法,让领导做选择题,而不是问答题
4. **计划可对齐** —— 下周 3 件事,每件写清目标或验收标准

同一个星期,两种写法:

| 流水账写法 | 有判断的写法 |
|---|---|
| 周一开需求评审会,周二改方案,周三和设计对稿 | 完成 XX 方案定稿,确定 3 个核心场景,预计下周进入开发 |
| 数据效果一般,继续优化 | 转化率 2.1%,低于目标 3%;已定位落地页 2 个问题,下周做 A/B 验证 |
| 下周继续跟进项目 | 下周:完成 A 模块上线验收(周四),B 需求评审(周五) |

### 结构模板(可直接套)

1. **本周核心成果** 3 条以内,每条 = 结果 + 量化 + 价值或影响
2. **关键进展** 按项目分组,写清当前状态和下一步
3. **问题与方案** 卡点 + 原因 + 你建议的方案 + 需要的支持
4. **下周计划** 3 件优先级最高的事,标注预期完成时间
5. **经验沉淀(可选)** 可复用的方法、踩过的坑

> 岗位和团队文化不同,结构可以调;但**「成果 / 风险 / 计划」三块不能少**。

### 这些判断 AI 替不了你

| 判断 | 为什么必须你来 |
|------|--------------|
| 哪件事是本周真正的成果 | AI 不知道你的 OKR 和团队优先级 |
| 一件事情的「价值」怎么定性 | 同一条数据,可能是亮点,也可能是隐患 |
| 哪个风险要上报、报到什么程度 | 涉及组织关系与决策权限 |
| 哪些内容不写 | 有些进展不适合公开,有些功劳不该自己说 |

**一句话:AI 能帮你写完整,但没法帮你写「对」。**

## 工具篇:用办公 Agent 做快做好

> 方法定了,再用工具。首选 [WorkBuddy](/workbuddy)(2.3 成品办公 Agent 工作台);TraeWork、千问办公等同类工具,流程一样。

### 人机分工

| 环节 | 谁做 | 产出 |
|------|------|------|
| 定本周 3 个核心成果与优先级 | **人** | 周报骨架 |
| 收集素材:文档、表格、待办、聊天记录 | **AI** | 按项目归类的素材清单 |
| 提炼定性:价值、数据口径、风险 | **人** | 结论与判断 |
| 成稿、排版、格式转换 | **AI** | 结构完整的初稿 |
| 校准与终审 | **人** | 可发送的终版 |

### 执行前:三件准备

1. **建一个「本周素材」文件夹**:本周的日报、会议纪要、数据截图、需求文档、待办清单都放进去
2. **先自己写下 3 个核心成果**(一句话一条),不要让 AI 猜
3. **确认数据口径与保密边界**:哪些数字能用、哪些内容不能进 AI 工具

### 让 AI 写出「更好」周报的 5 个用法

大多数人只把 AI 当「代写」,这是最浪费的用法。它更强的角色是**编辑、审稿人和对手**:

| 用法 | 怎么问 | 解决什么 |
|------|--------|---------|
| **1. 只当编辑,不当作者** | 「这是我写的草稿 + 本周素材,帮我压缩到 500 字,只保留结果和判断」 | 避免 AI 腔和空话,保留你的观点 |
| **2. 补漏** | 「对照素材,指出草稿里漏掉的成果、数据和风险」 | 你容易陷在细节里,AI 擅长穷举 |
| **3. 反向审稿** | 「逐条检查:哪些结论没有数据支撑?哪些词是空话?」 | 把「看起来不错」变成可验证 |
| **4. 换位质疑** | 「以我领导的视角,对这份周报提 3 个最可能追问的问题」 | 提前补强,减少被追问 |
| **5. 对比迭代** | 「对比这两版,说明改进点,并指出还有哪些地方不可信」 | 让每轮修改有依据,不是凭感觉 |

> **核心心法:让 AI 挑毛病,比让它写初稿更能提升质量。** 初稿给你 70 分,审稿和补漏把你送到 85 分以上。

### 执行中:四步走

#### Step 1 人:先搭骨架(5-10 分钟)

在备忘录里写下:

```
本周 3 个成果(一句话一条):
1. ...
2. ...
3. ...

风险 / 卡点:
- ...

下周 3 件事:
- ...
```

**不要跳过这步。** 这是你整周工作的判断浓缩,AI 无法从素材里替你推出来。

#### Step 2 AI:整理素材,填充骨架

把「本周素材」文件夹 + 上面的骨架一起交给 WorkBuddy,要求按项目归类、只保留与骨架相关的信息。素材多时先让它列「素材清单」,你确认后再成稿。

#### Step 3 人:校准(最关键的一步)

逐条检查:

- 成果有没有被说小或说大?
- 数字口径对不对、能不能回源?
- 风险描述是否准确、有没有带上你的方案?
- 有没有 AI 编出来的内容?**重点核对数字、人名、日期、项目名**

#### Step 4 AI:润色、排版、交付

统一措辞和格式;需要发邮件、做汇报 PPT 时,让它按目标格式输出。最后一关仍然是你的:读一遍,像不像你本人写的。

### 完整提示词模板(可直接复制)

```
你是我的周报助理。请基于我提供的骨架和本周素材文件夹,生成周报初稿。

本周骨架:
[粘贴 Step 1 的内容]

要求:
1. 结构:本周核心成果(≤3 条)→ 关键进展 → 问题与方案 → 下周计划
2. 每条成果写成「结果 + 数据 + 价值」,不写过程
3. 问题必须带 1-2 个建议方案
4. 下周计划不超过 3 条,标明预期完成时间
5. 只用素材里出现过的事实和数字;找不到依据的标注「待确认」,禁止编造
6. 语气专业简洁,符合向上汇报风格

输出:Markdown,先给结构,再给正文。
```

**模板里最值钱的是第 5 条**:把「不许编」写进约束,能挡掉大部分幻觉。

### 进阶:从「每次写」到「自动跑」

| 阶段 | 做法 | 效果 |
|------|------|------|
| 一次性 | 手动准备素材 + 用上面的模板 | 单次省 20-30 分钟 |
| 模板化 | 把骨架结构和提示词存成模板或 Skill | 每周只需填骨架 |
| 自动化 | WorkBuddy 定时任务每周五读取素材文件夹,预生成初稿 | 打开就有初稿,只做判断 |

> 注意:自动化只能自动化「执行」,不能自动化「判断」。**定时任务生成的是初稿,不是终稿。**

### 验收清单(发送前)

- [ ] 每条成果都有数据或事实支撑
- [ ] AI 给出的每个数字都能在原始素材里找到
- [ ] 问题都带上了方案
- [ ] 下周计划与领导预期对齐
- [ ] 没有把过程写成成果
- [ ] 没有泄露敏感信息
- [ ] 通读一遍:像不像你本人写的

## 复盘:这套方法能迁移到哪些场景

| 场景 | 方法篇(不变) | 工具篇(会变) |
|------|-------------|-------------|
| 月报 / 季度总结 | 成果、风险、计划的取舍逻辑 | AI 汇总周期素材、生成环比对比 |
| 汇报 PPT | 受众、结论先行、论据结构 | AI 出大纲、转 PPT、配图 |
| 方案文档 | 目标拆解、方案对比、可行性 | AI 收集资料、补论据、排版 |
| 竞品调研 | 调研维度、信息来源、判断标准 | AI 联网收集、整理对比表 |

**统一逻辑:先想清楚「什么算好」,再让 AI 帮你更快做到。** 这也是 [基础认知 · 人机分工原则](/concepts#人机分工原则) 在具体任务上的展开。

## 这个剧本的「套路」

| 套路 | 为什么 |
|------|--------|
| 先给判断,再让 AI 写 | 重点是人的判断,不是 AI 的猜测 |
| 让 AI 当审稿人 | 挑毛病比写初稿更能提升质量 |
| 数字必须回源核对 | AI 会编,周报里的假数字代价最大 |
| 沉淀模板与定时任务 | 把重复劳动交给流程,把判断留给自己 |
