# 从这开始

> 第一次来,别先看体系。**给你 20 分钟,做一份能交差的周报。** 做完你就知道这套东西怎么用了。

::: tip 没有周报任务?
随便找一件这周做过的活也行:写方案、整理文档、改代码,三步是一样的。如果都没有,从[任务列表](/#选一个任务开始)挑一个。
:::

## 开始前,先抓三样东西(2 分钟)

不用打开任何工具,先在备忘录里写:

- **本周做过的 3 件事**
- **能支撑它们的数字或结果**(哪怕只是「3 个渠道」「5 万用户」「12 份调研」)
- **一个卡点 + 你倾向的解法**

写不出来?那说明问题不在 AI,在你自己还没想清楚 —— 先把这三行写出来,再往下走。

## 第 1 步:让 AI 出初稿(5 分钟)

打开 [WorkBuddy](/workbuddy)(或你已有的办公 Agent),把下面这段连同你的三行素材一起发过去:

```
你是我的周报助理。基于以下信息,按「本周成果 / 关键进展 / 问题与方案 / 下周计划」写周报初稿。

本周 3 个成果:
[写你的三行]

关键数字:
[写数据;没有就写"暂无"]

卡点:
[写卡点和你倾向的解法]

下周 3 件事:
[写三件]

要求:
1. 每条成果 = 结果 + 数据 + 价值,不要写过程
2. 问题必须带 1-2 个方案
3. 只用我给出的数字;缺的标「待确认」,禁止编造
4. 全文不超过 800 字
```

> 更完整的提示词、人机分工和自动化玩法,在[周报剧本 · 工具篇](/playbook/weekly-report#工具篇-用办公-agent-做快做好)。

## 第 2 步:校准(10 分钟)

初稿不能直接发。逐条问自己四个问题:

1. **每个数字都对吗?** 能不能在原始素材里找到出处?
2. **成果有没有被说小或说大?** AI 不知道你的 OKR 和团队优先级
3. **每个问题都带方案了吗?** 让领导做选择题,不是问答题
4. **有没有 AI 编出来的内容?** 数字、人名、日期、项目名重点核对

改完这一步,你会得到一份「像你本人写的」周报。

## 第 3 步:发出去(3 分钟)

- 通读一遍,像不像你本人写的
- 检查有没有不该公开的信息
- 把这次用的提示词存下来,下次直接复用

## 做完之后

- 想看完整示例、更深的写法和验收清单:[写好一份周报](/playbook/weekly-report)
- 手上不是周报任务:[多文档汇总 / Excel / 工程任务](/#选一个任务开始)
- 想系统走一遍:[学习路径](/learning-map)

## 常见担心

**我不会写代码,能学吗?**
能。这份体系大部分内容与「写代码」无关:定义问题、给上下文、做判断、验收结果。你可以一直选办公类任务。

**我是工程师,这里内容会不会太浅?**
直接走工程剧本:[加一个功能](/playbook/add-feature) → [修一个 Bug](/playbook/fix-bug) → [重构一段代码](/playbook/refactor)。重点在拆解、审查与验收,不是代码补全。

**数据安全吗?**
敏感文件优先用本地模式;原则:不确定能不能给的,先不给。边界见[安全与验证](/safety)。

**工具以后换了怎么办?**
方法不依赖工具。先学「怎么把事做对」,工具只是执行端。
